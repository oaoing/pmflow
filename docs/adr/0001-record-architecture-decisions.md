# ADR-0001: 아키텍처 결정을 ADR로 기록한다

- 상태: 수용됨 (Accepted)
- 날짜: 2026-09-06

## 컨텍스트

이 프로젝트는 상태머신 설계, 채번 전략, 테스트 인프라 등 되돌리기 어려운 결정을
여러 건 내린다. 결정의 **배경과 대안**이 코드에는 남지 않으면, 나중에
"왜 이렇게 했지"를 재구성하는 비용이 크고, 같은 논의를 반복하게 된다.

포트폴리오 성격상 "무엇을 만들었나"보다 **"왜 그렇게 결정했나"** 를 보여주는 것이
중요하다.

## 결정

주요 아키텍처·설계 결정을 ADR(Architecture Decision Record)로 남긴다.

- 위치: `docs/adr/`
- 파일명: `NNNN-kebab-case-title.md` (4자리 일련번호)
- 형식: MADR을 간소화한 아래 골격
  - 상태 / 날짜 / 관련 링크
  - 컨텍스트
  - 결정 동인 (선택)
  - 검토한 선택지
  - 결정
  - 결과 (긍정 / 트레이드오프 / 재검토 트리거)
- 상태값: `제안됨(Proposed)` → `수용됨(Accepted)` → 필요 시 `대체됨(Superseded by ADR-XXXX)` / `폐기됨(Deprecated)`
- 한 번 `수용됨`이 된 ADR은 수정하지 않고, 번복 시 새 ADR로 대체한다.

## 결과

### 긍정적

- 결정의 맥락이 저장소 안에 함께 버전 관리된다.
- 신규 참여자·리뷰어가 설계 의도를 빠르게 파악한다.

### 트레이드오프

- 결정마다 문서 작성 부담. → "되돌리기 어렵거나 논쟁적인 것"으로 대상을 한정해 완화한다.
  사소한 선택(라이브러리 버전 등)은 대상이 아니다.
