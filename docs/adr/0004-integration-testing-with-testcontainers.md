# ADR-0004: 통합테스트 인프라로 Testcontainers를 사용한다

- 상태: 수용됨 (Accepted)
- 날짜: 2026-09-06 (제안) / 2026-09-06 (수용)
- 관련: [ADR-0002](0002-state-machine-implementation.md)(상태머신) · [ADR-0003](0003-numbering-strategy.md)(채번 전략) · [domain-model.md](../domain-model.md) 부록(테스트 도출)

## 컨텍스트

테스트 대상을 성격별로 나누면:

| 성격 | 예 | DB 필요 여부 |
|------|-----|-------------|
| 순수 도메인 로직 | 상태 전이 매트릭스(ADR-0002), 채번 포맷 문자열 생성, 정합성 규칙 판정 | 불필요 |
| DB 의존 동작 | 채번 동시성(ADR-0003), R01/R02 정합성 쿼리, `REQUIRES_NEW` 트랜잭션 경계, JPA 매핑·유니크 제약, cron 기반 실행 생성 | 필요 |

DB 의존 항목 중 특히 **채번 동시성**(ADR-0003)은 이 프로젝트의 핵심 검증 포인트다.
`SELECT … FOR UPDATE`, 원자적 `UPDATE`, 트랜잭션 격리 수준의 실제 동작은 DB 구현마다 다르므로,
**프로덕션과 동일한 DB 엔진**에서 재현·검증되어야 의미가 있다.

또한 이 검증은 로컬 개발자 환경과 CI(GitHub Actions) 양쪽에서 동일하게 재현되어야 한다.

## 결정 동인

1. 프로덕션 패리티 — 테스트 DB가 실제 DB와 락·트랜잭션·SQL 방언에서 동일하게 동작하는가.
2. 재현성 — 로컬과 CI에서 같은 결과가 나오는가, 환경 사전 설치 없이.
3. 격리 — 테스트 간 상태 오염이 없는가.
4. 피드백 속도 — 빠른 단위 피드백 루프를 해치지 않는가.

## 검토한 선택지

| 선택지 | 평가 |
|--------|------|
| A. H2 등 인메모리 DB | ❌ 빠르지만 `FOR UPDATE`·시퀀스·격리 수준 동작이 프로덕션과 달라 **동시성 테스트의 신뢰성이 없다**. 호환 모드는 근사치일 뿐 |
| B. 개발자 로컬/공유 DB 인스턴스 | ❌ 환경 사전 설치 필요, 테스트 격리 안 됨, CI 구성 부담 |
| C. Docker Compose로 DB를 띄우고 테스트가 접속 | △ 생명주기를 테스트 밖에서 수동 관리 → 스크립트 취약, "먼저 compose up" 규칙에 의존 |
| **D. Testcontainers** | ✅ 테스트 코드가 컨테이너 생명주기를 소유. 프로덕션과 동일 이미지, 자동 격리, CI 친화 |

## 결정

**D. Testcontainers + 프로덕션과 동일한 DB 이미지**를 사용한다.

### 테스트 계층 분리

- **단위 테스트** (`*Test`): 상태머신 전이 테이블, 채번 포맷 생성기, 도메인 규칙 판정. 스프링 컨텍스트·DB 없이 순수 JUnit. domain-model 부록의 ~30개가 대부분 여기 속한다.
- **통합 테스트** (`*IT` 또는 태그 분리): `@SpringBootTest` + Testcontainers. 채번 동시성, 정합성 규칙의 DB 쿼리 경로, 트랜잭션 경계, JPA 매핑·제약, cron 실행 생성.

### 구현 방침

- **컨테이너 재사용**: 싱글톤 컨테이너 패턴(정적 필드 + 최초 1회 기동)으로 통합테스트 클래스 간 공유. 클래스마다 기동하지 않는다.
- **연결**: Spring Boot `@ServiceConnection`으로 DataSource 자동 주입(수동 `@DynamicPropertySource` 최소화).
- **스키마**: 마이그레이션([ADR-0005](0005-schema-migration-tool.md), Flyway)을 테스트에도 그대로 적용 → 프로덕션 스키마 생성 경로를 함께 검증한다. `ddl-auto`는 통합테스트에서도 쓰지 않는다.
- **데이터 격리**:
  - 일반 통합테스트: 메서드 단위 `@Transactional` 롤백.
  - **동시성 테스트**: 별도 스레드/커넥션을 쓰므로 `@Transactional` 롤백이 불가능하다. 스레드풀 + `CountDownLatch`로 경합을 만들고, 테스트 종료 시 대상 테이블을 명시적으로 정리한다.
- **CI**: GitHub Actions `ubuntu-latest`는 Docker를 기본 제공하므로 추가 설정 없이 Testcontainers가 동작한다.

## 결과

### 긍정적

- ADR-0003의 동시성 주장을 말이 아니라 **재현 가능한 실패 테스트 → 통과 테스트**로 증명할 수 있다.
- 로컬과 CI 결과가 일치. "내 PC에선 됐는데" 제거.
- JPA 매핑·유니크 제약·마이그레이션이 실제 DB에서 검증된다.

### 트레이드오프

- **Docker 의존**: 로컬 개발자는 Docker(또는 호환 런타임)가 필요하다. README에 전제로 명시한다.
- **기동 시간**: 통합테스트 최초 실행에 컨테이너 기동 비용(수 초)이 있다. → 싱글톤 재사용 + 단위/통합 분리로 일상 피드백 루프는 단위 테스트가 담당하게 한다.

### 재검토 트리거

- 통합테스트 스위트 시간이 CI 허용치를 넘으면 → 태그로 분리해 nightly 파이프라인으로 이동, PR에서는 핵심 셋만 실행.
- 다중 DB 엔진 지원이 요구되면 → 컨테이너 이미지 매트릭스로 확장.
